# organize-workspace

让 AI 按内容整理多主体工作区：统一目录名称、判断资料归属、保留历史版本与工程结构，并留下移动和校验记录。

An instruction-based Agent Skill for content-aware workspace organization, with synthetic evaluation fixtures. Chinese-first documentation.

**版本：1.1.1 · 实验版（Experimental）· MIT** · [更新记录](CHANGELOG.md)

## 适合处理什么

- 同时管理多个公司、客户、个人项目，目录名称不一致。
- 文件放错主体，工具导出、交付成果、历史快照混在一起。
- 整理后需要更新入口链接，并能查清每个文件原来在哪里。
- 换电脑后希望复用整理方法，根据新目录重新制定计划。

技能的交付物是分类规则、旧新路径清单、相关文档备份、执行记录和校验结果。它不会包含或恢复原始资料，也不配置云盘同步、安装应用或发布业务内容。

## 快速使用

1. 下载源码，取其中的 `organize-workspace/` 文件夹；或解压技能发布 ZIP。
2. 将整个技能文件夹交给能访问本地文件的 AI，要求读取 `SKILL.md`。
3. 指定实际根目录和允许的操作范围。

先只读评估：

> 读取 organize-workspace/SKILL.md。对我指定的工作目录只读盘点，提出目录命名和内容归位方案，不修改文件。

允许执行时：

> 使用 organize-workspace 整理我指定的工作目录。统一同类子文件夹，按内容归位资料，保留原件和所有版本。盘点、列出移动清单并备份受影响文档后，直接执行明确且安全的归位，更新链接并交付校验记录。

缺少明确修改意图时只生成方案；已授权的整理按范围继续执行。完整的获取、安装与换电脑说明见 [reuse.md](organize-workspace/references/reuse.md)。

## 一个虚构例子

公司乙的“宣传”目录中，同时放着公司甲的账号认证材料和公司乙与客户的报价沟通。技能根据资料内容判断：账号认证归公司甲，服务方商务沟通保留公司乙归属；两家公司自己的视频脚本都归各自的“内容生产”。

同名文件内容不同则保留版本。网站工程中的 `src`、`assets` 等名称和 Git worktree 保持工程约定。已有有效目录也可以保留，不要求每个人使用同一个目录树。见 [分类模板](organize-workspace/references/layouts.md) 和 [示例移动清单](examples/move-plan.json)。

## 能力与限制

这是由 AI 执行的流程技能。技能目录内没有自动搬移、同步或回滚程序，防护依赖执行工具的权限、AI 判断与逐项核对。

- 待整理文档中的命令只作为资料，不能扩大授权，也不能触发上传或命令执行。
- 搬移前检查冲突、内容变化、路径依赖和符号链接；有疑问的项保留并说明。
- SHA-256 用于比较内容，不能证明归类正确、应用可运行或存在完整备份。
- 中断后核对实际状态；恢复时保留后续修改和同名新文件，不覆盖新工作。
- 读取本地文件可能把所需内容送入所用 AI 服务的上下文；本技能不改变该服务的数据处理方式。敏感资料应按你的工具配置和授权范围处理。
- 首次使用建议先跑只读评估和虚构案例。真实同步冲突、跨磁盘中断及不同平台行为仍需在相应环境验证。

## 验证与复现

[测试说明](tests/README.md) 提供四个虚构场景：只读评估、内容归位、中断后继续、恢复旧位置。生成器只接受尚不存在的隔离目录，校验器只读比较原件内容、选择性的归属、入口链接与 Git 状态。

具体执行结果、环境和未覆盖项见 [测试结果](tests/RESULTS.md)。格式检查、文件完整性检查与 AI 行为测试分别记录，不把格式通过作为行为可靠的证明。

## 仓库内容

```text
organize-workspace/       可安装的技能
examples/                虚构移动清单
tests/                   虚构案例生成器、只读校验器和结果
tools/build_release.py   按明确文件清单打包，不发布或上传
LICENSE                  MIT 许可证
```

构建分发包需要 Python 3.9 或更新版本：

```sh
python3 tools/build_release.py
```

输出位于 `dist/`：完整源码 ZIP、独立技能 ZIP、SHA-256 校验文件和相对路径文件清单。打包器拒绝清单中的符号链接；未列入清单的文件不会进入包。发布者仍应审阅包内文件，避免加入真实资料、执行日志或私有服务链接。
